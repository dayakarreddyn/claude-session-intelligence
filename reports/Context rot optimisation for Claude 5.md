# Measure fill, prune outputs, harden compaction

Session Intelligence's biggest context-rot opportunity on Fable 5.1 and Opus 5.5 is not a new threshold; it is that the plugin's ruler is broken, its only pruning mechanism never removes a token, and its compaction guidance travels through the lossiest channel Claude Code offers. The telemetry shows three "tokens" fields that share a name but not a unit (a cumulative chars/4 tool-I/O estimate stamped on every compact row and fed to the adaptive-zone learner, versus the per-call context size the zones and statusline actually compare), which pins the learner at its +30% clamp ceiling and manufactures 23 of 84 red-zone events above 1M from a 512 KB transcript-tail fallback. The tool archive has stored 1,045 snapshots (39.87 MB) with 0 recalls because nothing is ever removed from context, so there is nothing to recall. Meanwhile the models changed the ground rules: both run a 1M window that Claude Code only compacts at about 967K, both retain every prior-turn thinking block as input, neither receives any in-band context-remaining signal, and Fable 5.1's cache reads at 0.025x base price make compaction timing a pure quality decision rather than a cost one. The evidence base says rot is gradual and starts well under 300K (Opus 4.6 needle recall 99.7% at 100K to 69% at 800K), that raw tool observations are the dominant and most safely removable content (observation masking +2.6% solve rate at −52.7% cost; Anthropic's own context editing +29% at −84% tokens), and that compaction retains only 17% of standing constraints unless they live in a typed side-channel (90–96% with one). The prioritised programme therefore is: fix the measurement unit and record fill % against the real window; convert the archive into an active PostToolUse `updatedToolOutput` / PreToolUse `updatedInput` pruner; move decisions and constraints into a typed registry re-injected through the SessionStart `compact` matcher and verified with a new PostCompact hook; then restore numbers to the model-visible callout, correct the stale Claude 5 pricing rows, drop the cost-driven tightening, and recommend a lower per-model `autoCompactWindow`. Throughout, each claim is labelled as measured fact, Anthropic recommendation, or inference.

## Claude 5 sessions get no budget signal and retain every thinking block

The facts that change the plugin's design are all documented and all measured. **Fable 5.1 (`claude-fable-5-1`, released 1 Sept 2026) and Opus 5.5 (`claude-opus-5-5`, 22 Sept 2026) both run a 1M-token window as the default and maximum, with 128K max output and standard per-token pricing across the whole window**; there is no premium above 200K ([Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows); [Pricing](https://platform.claude.com/docs/en/about-claude/pricing)). In Claude Code, native-1M models "compact before the window fills, at about 967K tokens by default", a window the user can lower to anywhere in 100K–1M with `/autocompact`, `autoCompactWindow`, `--autocompact`, or `CLAUDE_CODE_AUTO_COMPACT_WINDOW` ([Model configuration](https://code.claude.com/docs/en/model-config)). The exact percentage behind "about 967K" is not stated, and Opus 5.5 is the default model on every paid plan while Fable must be selected explicitly ([Model configuration](https://code.claude.com/docs/en/model-config)). The practical consequence (inference) is that an unconfigured Claude 5 session spends most of its life in the 200K–900K regime, far above where any plugin zone currently fires and far above where the degradation evidence in the next section begins.

Two model-level facts about what occupies that window matter for a plugin that estimates context growth. First, **both models keep all prior-turn thinking blocks in context, and those blocks "count as input like any other conversation history"**; Anthropic's instruction is to "budget your context window as if thinking were ordinary conversation history, because it is" ([Thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)). Thinking cannot be disabled on either model (a `thinking: disabled` request returns 400), Fable 5.1 defaults to `high` effort in Claude Code, and Opus 5.5 defaults to `medium` but "tends to think more per turn than Claude Opus 5" ([What's new in Opus 5.5](https://platform.claude.com/docs/en/models/opus-5-5/whats-new-opus-5-5); [Models overview](https://platform.claude.com/docs/en/models/overview)). Second, the current tokenizer, introduced with Opus 4.7 and shared by both models, produces "roughly 30% more tokens" from the same text than pre-4.7 models ([What's new in Fable 5.1](https://platform.claude.com/docs/en/models/fable-5-1/whats-new-fable-5-1)). Any chars/4 estimator is therefore biased low on two counts (inference): it misses thinking entirely and under-counts the text it does see.

The most important fact for the plugin's role is an absence. **Fable 5.1, Opus 5.5 and the rest of the 4.7+/5.x line "don't receive" the API's injected `<budget:token_budget>` context-awareness tags, and the alternative, task budgets, "are not supported on Claude Code or Cowork surfaces"** ([Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows); [Task budgets](https://platform.claude.com/docs/en/build-with-claude/task-budgets)). The model in a Claude Code session on these models has no in-band knowledge of how full its context is. The only sources of that signal are the harness UI, which the model does not read, and whatever a hook injects. This reframes the plugin's zone callout from a courtesy nudge into the model's sole budget instrument, which bears directly on the `stablePrefix` default discussed below.

Cache economics flipped, and Anthropic says so explicitly. **Cache reads cost $0.25/MTok on Fable 5.1 (0.025x base) and $0.20/MTok on Opus 5.5 (0.05x), while 5-minute cache writes cost $12.50 and $5 respectively (1.25x base)**; across real traffic "agent loops read a median 84% of their input from the cache" and "deep in a task, a well-built loop pays full price on under 1% of its input" ([Pricing](https://platform.claude.com/docs/en/about-claude/pricing); [Optimizing for cost and intelligence](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence)). Anthropic's prompting guide for Fable 5.1 draws the conclusion: "compacting early to save cost may no longer be the right cost-intelligence tradeoff on Claude Fable 5.1, so experiment with later compaction points" ([Prompting Claude Fable 5.1](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1)). Carrying a warm 500K prefix costs roughly $0.125 per turn on Fable 5.1, and rebuilding a post-compaction prefix of 25K tokens costs about $0.31 (arithmetic from the published prices; inference). Cost no longer argues for or against compaction at any realistic scale; only quality does. The plugin's learner currently tightens the orange zone by ×0.88 when a session's cost exceeds the history p75, which is the wrong direction on these models.

Finally, the plugin must be append-only. On Fable 5.1 and Opus 5.5, "a thinking block stays valid only while everything you sent before it is unchanged on later requests"; clearing or shortening an earlier `tool_result` is an invalidating edit, and for accounts created on or after 31 Aug 2026 the API rejects the request unless the client opts into `drop_block`, which "can significantly increase the output tokens generated" ([Preserved thinking](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking)). Claude Code keeps that prefix intact itself; a plugin must never rewrite earlier transcript turns, and the only legitimate hook channels that reduce tokens are the ones that act before a result enters history: PostToolUse `hookSpecificOutput.updatedToolOutput` ("replaces the tool's result") and PreToolUse `updatedInput` ("replaces tool arguments") ([Hooks reference](https://code.claude.com/docs/en/hooks)). The other reachable channels are read-or-inject only: `additionalContext` on SessionStart, UserPromptSubmit, PreToolUse, PostToolUse and Stop, each capped at 10,000 characters with no override; PreCompact, which can veto compaction (exit 2) but cannot shape the summary and whose `systemMessage` is discarded; PostCompact, which receives the generated `compact_summary` read-only; and the SessionStart `compact` matcher, whose output Claude Code "adds to the compacted context" ([Hooks reference](https://code.claude.com/docs/en/hooks); [Explore the context window](https://code.claude.com/docs/en/context-window)). Context that hooks injected earlier in the conversation is "summarized with the rest" at compaction, so the SessionStart `compact` path is the only durable one. The API-side mechanisms (`clear_tool_uses_20250919`, `clear_thinking_20251015`, `compact_20260112`, on-demand `compaction`, the `memory_20250818` tool, explicit `cache_control`) all require request parameters or beta headers and are unreachable from a hooks-plus-statusline plugin ([Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing); [Compaction at a token threshold](https://platform.claude.com/docs/en/build-with-claude/compaction-threshold)).

## Rot is gradual, begins well under 300K, and comes from tool output and lossy compaction

No Anthropic source publishes an "effective context" figure or a degradation curve for either Claude 5 model. The system cards' only long-context benchmark is ProgramBench, an agentic coding task with episodes "up to the full 1M token window", on which **Opus 5.5 scores 91.2%, Fable 5.1 87.6% and Opus 5 85.4%**; both cards also admit "more limited coverage of long trajectories" ([Opus 5.5 System Card](https://www-cdn.anthropic.com/fc1b44717c85dc068bc6ba5024219938094694bd/Claude%20Opus%205.5%20System%20Card.pdf); [Fable 5.1 System Card](https://www.anthropic.com/claude-fable-5-1-mythos-5-1-system-card)). That benchmark mixes capability with context length and cannot be read as a rot curve (inference). Anthropic's current docs state the phenomenon qualitatively, "As token count grows, accuracy and recall degrade, a phenomenon known as context rot", and describe it as "a performance gradient rather than a hard cliff" ([Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows); [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)).

The best Claude-specific measurements are therefore one generation old, and they locate the gradient. **Opus 4.6 scores 93% on MRCR v2 8-needle at 256K and 76% at 1M** ([Opus 4.6 announcement](https://www.anthropic.com/news/claude-opus-4-6); [yage.ai compilation](https://yage.ai/share/long-context-benchmark-en-20260315.html)). Inside agent transcripts the loss is steeper: Anthropic Fellows found that monitors classifying coding-agent transcripts miss dangerous actions "2× to 30× more often" after 800K tokens of benign activity, with **Opus 4.6 (thinking) needle-injection recall falling from 99.7% at 100K to 69% at 800K** and non-thinking Opus collapsing to 5% when the event sits mid-transcript ([Classifier Context Rot, arXiv 2605.12366](https://arxiv.org/html/2605.12366v1)). Older controlled studies agree on shape: NoLiMa measured Claude 3.5 Sonnet's effective length at 4K of a 200K window, and Chroma's 18-model study found degradation driven by distractors, structurally coherent haystacks and low needle-question similarity rather than raw length, with Claude 4 models failing by abstention rather than hallucination ([NoLiMa](https://arxiv.org/html/2502.05167v3); [Chroma](https://www.trychroma.com/research/context-rot)). The two 2026 coding-agent studies add a nuance the plugin can use: relevant and irrelevant padding hurt equally (8/10 to 3/10 pass rate at 299K characters either way), so "keeping it because it is related" is not a safe rule, and degradation tracks dependent step count as much as token count, with naive truncation making it worse ([CertiK, arXiv 2607.17937](https://arxiv.org/html/2607.17937v2); [Mittal, arXiv 2609.01660](https://arxiv.org/pdf/2609.01660)). The synthesis (inference) is that there is no fill percentage at which quality collapses, measurable loss on retrieval-style tasks is visible by 256K on the best 4.6 model, and the 100K–800K band is where agent-transcript recall drops 10–30 points. Any zone fraction a plugin chooses is a heuristic, but a heuristic that keeps sessions below roughly a third of a 1M window is consistent with every curve found.

What to remove is better measured than when. **Observation tokens are about 84% of an average SWE-agent turn, and simply masking observations older than ten turns raised Qwen3-Coder's SWE-bench Verified solve rate from 53.4% to 54.8% while cutting cost 52.7%; LLM summarisation did no better and lengthened trajectories** ([JetBrains Complexity Trap](https://arxiv.org/html/2508.21433v3)). Anthropic's own context editing, which clears stale tool results, "delivered a 29% improvement" alone and cut tokens 84% in a 100-turn search eval, and the engineering guidance calls tool-result clearing "one of the safest lightest touch forms of compaction" ([Managing context](https://claude.com/blog/context-management); [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). Anthropic's cost docs report that on a long run "compaction saves 32% and pruning 39%" (cost, on an unnamed earlier model), with the Claude 5 caveat that client-side rewriting of earlier tool results invalidates later thinking blocks, "so use compaction instead" ([Optimizing for cost and intelligence](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence)). Claude Code's own order of operations matches: "It clears older tool outputs first, then summarizes the conversation if needed", at an undocumented threshold ([How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)). No study isolates verbose thinking or stale plans as degraders, so recommendations about those are inference only.

Compaction itself is the second measured loss, and it is concentrated in standing rules rather than narrative. **Across the COMPINT benchmark, compactors "retain only 17% of injected session constraints on average"; a plug-in constraint registry restored retention to 90.3–95.1% and compliance to 93.4–96.3%** ([Lost in Context Compaction, arXiv 2608.11242](https://arxiv.org/html/2608.11242)). Directly relevant to this harness, **Claude Code's `/compact` prompt run on Sonnet 4.6 "preserves 53% of safety rules after one compaction round and 10% after five"**, while a type-aware compactor held 96% recall over five rounds ([The Compaction Cliff, arXiv 2608.22752](https://arxiv.org/abs/2608.22752)). Drift compounds because each summary discards facts the next cannot see: a reference experiment held reversible retrieval near 0.95 recall versus 0.33–0.56 for irreversible summarisation ([Rate-distortion survey, arXiv 2607.08032](https://arxiv.org/html/2607.08032v1)). FIFO truncation matched or beat summary compaction at moderate budgets, and the first action after a compaction boundary produced 0.108 more blocked or erroneous actions ([TRACE, arXiv 2608.06503](https://arxiv.org/html/2608.06503v2)). Anthropic's documented behaviour fits: the summary "replaces the verbatim conversation: full tool outputs and intermediate reasoning are gone", it re-reads up to five recently modified files (path-only above 5,000 tokens) and re-injects invoked skills capped at 5,000 tokens each and 25,000 total, and the recommended preservation levers are CLAUDE.md, a `# Compact instructions` section, `/compact <focus>`, and SessionStart `compact` hooks ([Explore the context window](https://code.claude.com/docs/en/context-window); [Manage costs](https://code.claude.com/docs/en/costs)). The long-running-agent post goes further, "compaction isn't sufficient", and keeps feature state in JSON "because the model is less likely to inappropriately change or overwrite JSON files compared to Markdown files" ([Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). Delegation evidence is the weakest of the three: Anthropic measured +90.2% on an internal research eval from fresh-context subagents and 2.7x latency gains for Opus 5.5 agent teams, but the one attempt to use delegation as rot containment in coding failed when "the worker lost an opaque contract after three native compactions" ([Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system); [Opus 5.5 System Card](https://www-cdn.anthropic.com/fc1b44717c85dc068bc6ba5024219938094694bd/Claude%20Opus%205.5%20System%20Card.pdf); [CertiK](https://arxiv.org/html/2607.17937v2)). Delegation moves the problem; it does not solve it unless the delegated task fits in one clean window (inference).

## SI measures the wrong number and its only pruning lever never removes a token

The plugin audit, run read-only against HEAD `24acf0b` and the live telemetry, is where the measured facts are least flattering and most actionable. **Three fields named "tokens" carry two units.** The PostToolUse budget hook accumulates `100 + ceil(chars/4)` per call across the session, and that cumulative tool-I/O estimate is what PreCompact stamps on every compact row, what the Stop hook writes as `peak_tokens`, and what `compact-history.jsonl` feeds to the adaptive-zone learner ([si-token-budget.js:111-145](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/hooks/si-token-budget.js); [si-pre-compact.js:694-696](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/hooks/si-pre-compact.js); [si-stop.js:131-157](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/hooks/si-stop.js)). The zone-crossing hook and the statusline instead read the last assistant `usage` block from the transcript tail and use `input + cache_creation + cache_read`, the per-call context size ([lib/utils.js:188-212](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/lib/utils.js); [si-suggest-compact.js:168-192](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/hooks/si-suggest-compact.js)). The measured result is that compact-row "tokens" run at **p50 1.58M and p90 3.71M** over 30 days, numbers larger than the model's window, while zone crossings cluster at 263–370K (yellow), 343–500K (orange) and 520K+ (red) ([stats.js over si-events.db](file:///Users/0xd/.claude/state/si-events.db)). Because `round(p50 × 0.9)` of a cumulative series is always above the 390K clamp, **the adaptive learner is pinned at its ceilings (yellow 310K / orange 390K / red 520K, or 263K / 343K when cost-tightened)**, which is exactly where the observed crossing minima sit; the "learning loop" is a constant +30% widening of the static zones ([lib/compact-history.js:153-253](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/lib/compact-history.js)).

A second measurement defect inflates the headline statistic the stats tool uses to say sessions are "routinely pushing past the recommended compact line". When the 512 KB tail scan fails to find a `usage` line, the hook falls back to the cumulative estimate, and the log shows **all 13 red callouts above 1M in the last 30 days were immediately preceded by `tokenSource: "estimate"`**; 23 of the 84 red crossings over 90 days are above 1M, and the 25 `green → red` jumps are the same artifact re-arming ([session-intel logs](file:///Users/0xd/.claude/logs/); [si-events.db](file:///Users/0xd/.claude/state/si-events.db)). No field anywhere records fill % at compaction, so the data cannot say how full the window was when Claude Code auto-compacted, and no outcome metric exists that could correlate context size with quality.

Zones are absolute and model-blind: `{ yellow: 200000, orange: 300000, red: 400000 }` is the single source of truth, duplicated in the budget hook, and `getZone()` compares raw counts regardless of window ([lib/config.js:81](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/lib/config.js); [si-token-budget.js:342](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/hooks/si-token-budget.js)). A `contextCap` resolver exists only in the statusline (config override, then Claude Code's `context_window.context_window_size`, then a model-id regex, then 200K), and a grep for `contextCap|context_window` across `hooks/` and `lib/` returns nothing ([statusline-intel.js:610-636](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/statusline/statusline-intel.js)). On a 1M model red fires at 40% of the window, which happens to be defensible given the evidence above; on a 200K session (`CLAUDE_CODE_DISABLE_1M_CONTEXT=1` or an unrecognised gateway id) yellow fires at 100%.

**The tool archive is the plugin's only mechanism that touches tool output, and it is explicitly "Observational only. We do not truncate or rewrite the result the model just received."** It has stored 1,045 snapshots in 90 days, averaging 103,625 characters for `Read` (about 26K tokens, maximum 612,739 characters) and 11,910 for `Bash`, with **0 recalls lifetime across 1,112 rows**, even after the PreCompact block began listing the six largest ids ([si-tool-archive.js:12-15](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/hooks/si-tool-archive.js); [si-events.db](file:///Users/0xd/.claude/state/si-events.db)). The reason is structural (inference): nothing is ever removed from context, so the model has no occasion to replay anything. The archive proves that results an order of magnitude larger than Claude Code's documented 25,000-token file-read cap are routinely entering context (these must be `allow_large` reads), and that the plugin has the id, tool, size and preview of every one of them and does nothing with that knowledge.

The compaction path has the right skeleton and the wrong channels. The PreCompact hook streams a ten-section markdown block to stdout, which Claude Code folds into the summariser's context; it includes "must preserve" lines from `session-context.md`, the HOT/COLD directory shape, memory-offload and priorities prompts, and the archive ids, and exits 0 ([si-pre-compact.js:578-636](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/hooks/si-pre-compact.js)). All of that is subject to the summariser's 17–53% retention. The SessionStart `compact` handoff, the one durable channel, replays git state, the Current Task and in-flight files but **not the Key Decisions or any constraint list** ([lib/handoff.js:192-257](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/lib/handoff.js)). The design doc still states Claude Code "exposes no PostCompact hook"; the hook has existed since v2.1.76 and delivers `compact_summary`, and `hooks.json` registers only SessionStart, UserPromptSubmit, PostToolUse, PreCompact and Stop ([docs/context-engineering.md:458](file:///Users/0xd/DWS/claude-session-intelligence/docs/context-engineering.md); [Hooks reference](https://code.claude.com/docs/en/hooks); [hooks.json](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/hooks/hooks.json)). Nothing checks whether the ten-section block stays under the 10,000-character hook-output cap beyond which Claude Code substitutes a 2,000-character preview and a file path; whether it ever exceeds that is unmeasured and worth logging.

The model-visible signal was deliberately blinded. With the default `compact.stablePrefix: true`, the zone callout the model sees reads "[StrategicCompact] Drift zone. Advisory only — continue if the task needs full context." plus a directory diagnosis and a rotating tip, with the token count, cost and thresholds stripped on the rationale that "the cache win (read cost −90% for the post-compact prefix) outweighs losing exact counts" ([si-suggest-compact.js:361-373](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/hooks/si-suggest-compact.js); [lib/config.js:131-140](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/lib/config.js)). The measured payoff is absent: the stable-prefix fingerprint **drifted on 25 compacts and matched on 2**, because the Preserve list is a top-five of recency-scored directories that rotates with the work, and the **90-day post-compact cache-hit mean is 0.379** ([session-intel logs](file:///Users/0xd/.claude/logs/); [compact-history.jsonl](file:///Users/0xd/.claude/logs/compact-history.jsonl)). The behavioural result is consistent with a blinded signal: the heaviest sessions logged 37 and 16 compacts each, drew 26 and 17 red callouts, and the six most recent CSM compacts were all `trigger = auto` at cumulative estimates of 3.4–4.7M; the advisory never converted into a manual compact in the sessions that needed it ([si-events.db](file:///Users/0xd/.claude/state/si-events.db)).

Model awareness today is pricing-only and stale. `PRICING_BY_MODEL` has `'claude-fable'` at cache-read $1.00, which is Fable 5's rate, not Fable 5.1's $0.25; `claude-opus-5-5` resolves by prefix to the generic `'claude-opus'` row at $5 / $6.25 / $0.50 / $25 against actual $4 / $5 / $0.20 / $20; and `claude-sonnet-5-5` resolves to the standard Sonnet row at $3 / $15 against actual $2 / $10 ([lib/cost-estimation.js:38-78](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/lib/cost-estimation.js); [Pricing](https://platform.claude.com/docs/en/about-claude/pricing)). The `costBand()` helper that was meant to modulate thresholds by cache ratio has no caller, nothing in hooks or lib references a cache TTL, and `session_model_costs` sums to roughly $13.4K over 90 days against $7.0K from Claude Code's own `total_cost_usd`, an unreconciled gap ([lib/cost-estimation.js:268-292](file:///Users/0xd/DWS/claude-session-intelligence/plugins/session-intelligence/lib/cost-estimation.js); [si-events.db](file:///Users/0xd/.claude/state/si-events.db)). Telemetry integrity issues compound the picture: the JSONL history holds 44 compacts over 30 days where the DB mirror holds 30; the compact `Total cost` sums cumulative session cost per row and so double-counts; and 372 of 748 agent rows are unpriced.

## Fourteen changes, ranked: fix the ruler, prune outputs, type the handoff

The programme below is ordered so that each tier makes the next measurable. Nothing in tiers 1–3 requires an API-only mechanism; every change uses a hook field, a settings recommendation, or the statusline payload that Claude Code already provides. Three of these deserve argument beyond the table. The pruner (row 4) is the single highest-leverage change because it is the only one that removes tokens, and the evidence for removing exactly this class of token is the strongest in the literature; but it carries a real tradeoff. Claude Code already caps a file read at 25,000 tokens, a Bash result at 30,000 characters, and an MCP result at 25,000 tokens, writes text results over 50,000 characters to a file, and clears older tool results itself at an undocumented point ([Environment variables](https://code.claude.com/docs/en/env-vars); [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)). The archive shows the results that escape those caps are mostly deliberate `allow_large` reads, where the model asked for the whole file. A pruner that silently replaces such a result with an excerpt will cause re-reads, which is why the measurement in row 4 pairs recall rate with a re-run counter and why the starting floor should be high (50K characters, roughly 12–16K tokens on the current tokenizer) and lowered only as the re-run counter stays flat. The preventive `updatedInput` path has no such tradeoff and is Anthropic's own worked example; it should ship first.

The typed registry plus PostCompact pair (rows 6 and 7) is the only change that attacks the measured compaction loss directly, and it converts the plugin's regret proxy into a real retention metric. Today `continuationQuality` averages about 0.8 and says only that post-compact work landed in HOT rather than DROP directories, which is evidence the directory hints are safe, not that anything important survived ([compact-history.jsonl](file:///Users/0xd/.claude/logs/compact-history.jsonl)). With `compact_summary` in hand, retention of each registry item becomes a string match, and the Compaction Cliff's 53%-then-10% curve becomes something the plugin can reproduce or refute on Claude 5 summaries, which no published study has yet done. The ordering inside the PreCompact block matters because of the 10,000-character cap: constraints first, then the shape, then the optional prompts, so that if the cap is ever hit the preview still carries what must survive.

The callout change (row 9) is where the plugin's philosophy meets the model facts. "Advisory, not directive" was a reasonable stance when the model could in principle sense its own budget; on Fable 5.1 and Opus 5.5 it cannot, and Claude Code's docs ask that hook context be written "as factual statements, not imperative instructions" ([Hooks reference](https://code.claude.com/docs/en/hooks)). A factual line such as "Context at 48% of a 1M window; auto-compaction at 967K; 3 results above 20K tokens in the last 40 calls" is both compliant with that guidance and the only budget information the model will ever see. Bucketing to 5% keeps the line stable across many calls, which recovers most of what `stablePrefix` was trying to buy without blinding the model.

Several things the plugin should explicitly not do follow from the same facts. It must not rewrite earlier transcript turns under any circumstances, because that invalidates every later thinking block on both models. It should not use PreCompact's exit-2 veto to delay auto-compaction, because when compaction "was triggered to recover from a context-limit error already returned by the API, the underlying error surfaces and the current request fails" ([Hooks reference](https://code.claude.com/docs/en/hooks)). It should not keep a chars/4 cumulative estimate as a primary metric on a tokenizer that yields 30% more tokens and on models that retain thinking as input; if the estimate survives as a diagnostic, recalibrate it to roughly 3 characters per token (inference from the published 30% figure) and present it as tool-I/O share, not context size. It should not treat mid-session `additionalContext` as durable across compaction. And it should not fight Claude Code's own tool-result clearing; the pruner's job is the long tail Claude Code's caps let through.

The gaps that no amount of plugin work closes are worth stating plainly. There is no Claude 5 retrieval-versus-length curve from any source, so the plugin cannot cite a degradation onset and should not pretend to; the honest framing in its docs is "no official number exists; these fractions are calibrated to the Opus 4.6 evidence and Claude Code's own API defaults of 100K for clearing and 150K for compaction". The quality effect of compaction on Claude 5 summaries is unmeasured anywhere, which is exactly why row 7 matters: the plugin's own PostCompact telemetry would be the first dataset on it. And the plugin records no outcome metric, so until rows 1 and 7 land, nothing in `stats.js` can say whether any change reduced rot rather than merely reduced tokens.

## Conclusion

The research reframes what "context intelligence" means for this plugin on Claude 5. The old model of the problem was a threshold problem: pick the right token number, nudge at the right time. The models made that model obsolete in both directions at once. Cost no longer argues for early compaction, because a warm 500K prefix on Fable 5.1 costs cents per turn; quality argues for it more than ever, because the window grew fivefold while the measured degradation band did not move, and because the model now has literally no in-band sense of its own fill. A plugin that only nudges, and nudges without numbers, is a thermostat with no display wired to a furnace that cannot feel heat.

The deeper implication is that the plugin's value is shifting from advice to instrumentation. Three of the fourteen changes (unit unification, fill % on every compact, PostCompact retention) produce no model-visible behaviour at all, yet they are the prerequisite for knowing whether any of the other eleven worked, and they would make Session Intelligence the first source of per-compaction retention and fill-at-compaction data on Claude 5 sessions, which neither Anthropic's system cards nor the academic literature currently provide. Once that instrumentation exists, the pruner and the typed registry are the two levers with measured upside in the literature, and the autoCompactWindow recommendation is the one lever that changes where sessions live on the degradation gradient. Everything else is tuning, and tuning without a working ruler is how the adaptive learner ended up pinned at its clamp for a year without anyone noticing.
